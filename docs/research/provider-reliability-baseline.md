## Additional findings beyond the report's T01–T10 shortlist

These are substantiated code-path gaps/candidates, **not executed reproductions**. They must receive failing tests before being called fixed. Distinguish established missing behavior from a possible harmful interleaving.

Repro fixture: hold an old minimal-message response, perform markRead/archive remotely and settle it, then release the stale read; assert user intent remains until a fresh observation confirms it. SC589/II270 cover only an unsettled op, not this boundary. A06/A19 require delivered overlays or observation-generation fencing. This is broader than T05's partial-step retries.
2. **X02: refresh-token rotation is ignored; renewed consent omitting a refresh token is rejected (established source gap, provider impact conditional; W04).** `gmail.ts:151` response type contains only access_token/expires_in/error; successful refresh stores only access in memory, never a returned refresh_token. `connectGmail` requires a new refresh_token even for same-identity renewed consent (`:116`). Test synthetic rotation that invalidates old refresh credential, persistence failure/restart, stale rotation vs reconnect and omitted replacement retaining verified same-identity token. Do not assume Google rotates on every refresh or preserve a token across identity mismatch. T08's timeouts/scopes do not close this.
3. **X03: poison mail has no durable per-item repair owner and may repeatedly block account progress (established architectural gap; W03/W10).** `gmail-api.ts:186` Promise.all rejects if one raw fetch/parse fails; `imap.ts:441` awaits parse inside batch loop with no per-item isolation/repair state. All successful neighbors may be retried after crash, and malformed item can repeatedly fail the pass. Test malformed and oversized raw plus good neighbor, restart and healthy account indicator; either keep cursor behind failed work or atomically own a repair record. This also addresses S08/S56; not solved by T06's 404 distinction.
4. **X04: HTML-only matching can include invisible text (established normalization gap; W10).** `mime.ts:43` removes script/style/head blocks and all tags but does not exclude `hidden`/`display:none` descendants; `parseRaw` uses it when no plain alternative. Test a body condition/action end to end in both stores, entity/whitespace/case semantics and useful visible text. Preserve current plain-text precedence and no-network inert parsing. B37 is actual local-domain work, beyond T01–T10.
