## Recommended bounded contract

Use **per-message/field intent ownership plus an account causal epoch captured before provider observation begins**. Maintain effective booleans in existing messages rows so list/count/search readers remain unchanged. Keep provider observation order distinct from local intent versions and provider history IDs.

This is a proposed extension of existing atomic store commands, not an existing callable interface. A pending-only patch can ship as a separate regression correction, but must remain marked X01 incomplete.

### Meaning of a causal epoch

One durable per-account monotonic integer is advanced in the store at (a) beginning a provider sync observation pass, (b) committing new/replacement local intent, and (c) recording successful delivery or a terminal/canceled intent transition. Allocate and compare in the serialized writer; never read an ambient clock. Never reset or recycle because ops were deleted. Use a safe-integer checked representation shared by SQL/IDB; fail allocation before precision loss rather than silently coalescing epochs. If root chooses decimal strings instead, implement one shared exact comparator; never Number-cast provider history IDs.

Capture one epoch **before invoking provider.sync**, after current-life checks, and carry it unchanged through async network/processing/staging/sliced store calls. One durable command per pass, not per downloaded message. A whole old pass is conservatively old even if some of its later requests began after acknowledgement. This false-negative delays reconciliation until a fresh pass; the durable repair owner below makes that safe.

Do not mint an epoch when a stale payload finally reaches sink.ingest/updateFlags. Doing so would turn the bug into a false confirmation. Persisted enumeration/repair (plan33 D) must retain its original observation provenance when replaying an old captured payload. A *new* authoritative GET receives the new pass epoch. Direct imports/dev seeds without provider provenance remain explicitly unversioned; they may insert/update content, but cannot retire or override an owned local field. No default “fresh” invented at the ingestion boundary.

For this slice, rely on existing per-account pass serialization and latest-snapshot reads to avoid same-pass revision reordering. This epoch is not proof that arbitrary overlapping same-pass body/history deltas are ordered. A08 deletion/import ordering and plan33 durable multi-page replay still require provider revisions/tombstones or explicit per-observation ordinals. Do not claim those closed by pass epochs.

### Durable state shape (recommended, names subject to approval)

- One account epoch counter (new dedicated account column or account-keyed counter table, with account cascade; choose one, do not bury it in provider cursor JSON).
- Sparse `message_flag_intents`, PK `(message_id, field)`, for the five user-owned fields only: account_id, intent_version, desired, final_op_id nullable, phase pending/delivered/observed, barrier_epoch, last_observation_epoch. A latest intent row, not an append-only history. At most five rows per existing message.
- `final_op_id` references the latest **terminal provider step that establishes that field's final desired state**, not just whichever op acknowledged last. op target metadata carries captured intent versions for the fields it can establish. Compare version and owner on completion before marking delivered. Keep existing op_targets indexes/queue group behavior intact.
- A delivered/needs-snapshot partial index keyed by `(account_id,message_id)` supports bounded targeted reconciliation. IDB needs matching MemDb indexes plus object-store/version migration. Sparse rows become phase observed after a fresh authoritative snapshot; retain causal watermarks so older replay cannot regain ownership. These are passive bounded watermarks, not permanent value overrides.
- No raw bodies, subjects, addresses, arbitrary provider text, timers or TTLs in this state. Deletion cascades message-local metadata. Failed/unknown operations do not leave a permanently authoritative local override.

The observed value can remain the existing materialized message flag after ownership is retired; a separate full provider-shadow copy is unnecessary for this bounded contract. While pending, an observation of the same field need not be materialized. Cancellation retains the exact local inverse from the existing before state and creates a fresh-snapshot obligation; it does not assume that the server has stayed unchanged.

### Atomic transition rules

1. **Local action/filter/Undo:** update effective flags, record touched-field final intent and generations, queue/narrow/cancel operations, write search/feed effects together. Capture exact message targets as today. Field effects include provider-implied removals (trash→inInbox false, restore→trash/spam false), even when one such field was already locally false.
2. **No-op actions:** retain today’s no-send/no-learning/no-journal behavior. If a current pending/delivered transition could change a field that a user explicitly reaffirmed, that reaffirmation needs a new field generation/causal barrier even if the materialized boolean is already desired. Do not infer a generation for unrelated messages in a thread or for every benign duplicate click. Exact cases are listed in tests.
3. **Pending:** observations never replace fields owned by unresolved local steps. Other fields, sent/draft state and Gmail category labels remain eligible; update thread aggregates/facts/search from the resulting effective state. Do not skip a whole message because archive is pending.
4. **Old completion:** success for version V cannot deliver, clear or change version V+1. This holds after supersession, retry, target narrowing and an intervening read→unread or trash→restore. The operation's remote success is still recorded for queue recovery; field ownership is a separate conditional transition.
5. **Final step success:** atomically mark operation succeeded, remove its queue targets as today, and mark only matching latest field generations delivered with a newly allocated barrier epoch. Intermediate Undo steps do not deliver final location intent. Persist a snapshot-needed owner independently of ops so normal succeeded-op history cleanup cannot erase it.
6. **Pre-ack observation:** if its epoch is absent or not greater than the field's latest delivery/terminal barrier, preserve that effective field and the snapshot obligation. Matching values from old observations are not confirmation. Content and independent flags can still commit. A cursor can advance only because the skipped ownership is durable.
7. **Fresh snapshot:** if no unresolved local provider step remains for the field and the captured pass epoch is greater than its barrier and at least its last accepted observation epoch, accept the snapshot and retire the delivered value overlay. Matching desired confirms local convergence. A conflicting fresh authoritative snapshot represents the latest remote state and must also be allowed to retire the overlay; otherwise a legitimate external reversal before the first confirming read can be hidden forever. Keep the watermark to reject earlier payload replay. Compare-and-set against generation inside the same command, including after asynchronous attachment staging.
8. **Terminal failure/unknown:** retain visible operation failure as today, remove only matching current overlay authority, retain a terminal epoch/snapshot-needed obligation, and let a fresh authoritative snapshot reconcile actual provider state. Do not turn a failed local wish into an immortal fence. Auth/network parked and ordinary retrying operations remain pending. Send ambiguity stays entirely outside this flag contract.
9. **Unattempted inverse cancellation:** the queue may still delete the old op and return no new operation, but intent metadata must atomically move to a new generation with the restored effective value and snapshot obligation. A snapshot captured before the canceled optimistic action must not overwrite a still-newer field. Future fresh reads can show genuine external changes. Never require a nonexistent cancelled op to acknowledge.
10. **Crash/reopen:** delivered metadata and counter survive; pending operations recover through existing queues; old replay uses old provenance. First healthy sync reads delivered snapshot-needed targets even when its history cursor has no events. No startup mailbox-wide scan to reconstruct intentions from historical ops.

### Important scope limit: authoritative snapshot vs eventual consistency

The above contract solves observations whose acquisition began before the acknowledgement, delayed async commit, replay provenance, and later external changes under an authoritative post-ack read contract. Source-only inspection cannot establish a Gmail/IMAP service consistency guarantee for a supposedly fresh request that itself returns an arbitrarily old replicated/cache view. batchModify gives no mutation version. Do not claim an epoch proves the age of the server's returned data.

If stronger stale-*post-ack* protection is required, use validated per-message provider revisions tied to actual mutation acknowledgements (potentially changing Gmail write behavior) or explicitly verify authoritative read semantics. Matching-only overlays and guessed profile watermarks are not acceptable substitutes: the first can stick forever; the second can include a later external reversal that is then wrongly hidden. Root should approve this contract explicitly before implementation. No unsupported provider guarantee is added by this document.

# Read-only Codex critique

1. **Inverse cancellation can leave the newest generation without a sufficient barrier.** `packages/db/src/repos.ts:338–344` and `packages/idb/src/mail.ts:1175–1179` cancel queued B while running A survives. Example: A=read running, B=unread queued, C=read cancels B; a sync captures unread after C but before A succeeds, then commits after A settles. Rules 4/9 prevent A from delivering C, but C’s cancellation barrier predates that snapshot, so rule 7 can accept it. **Correction:** track surviving field-affecting predecessors and advance the current generation’s causal barrier when they settle, without granting them ownership. Cover success, failure, recovery and no-op reaffirmation.

2. **A fresh IMAP pass does not make cached locations authoritative.** `packages/mail/src/imap.ts:487` records COPYUID destinations with `flags: []`; `:283–287` searches only the window for a mailbox without cursor state, and `:402` skips its cached-location flag refresh. An older moved message can therefore reach the proposed snapshot-needed reconciliation with synthetic empty flags, falsely clearing read/star. **Correction:** obtain a UIDVALIDITY-checked flags observation for those locations before certifying the fields. Keep the obligation when no such observation occurred; adding IDs to `reconcile` alone is insufficient.

3. **The proposed IMAP reconciliation expansion can delete successfully moved mail.** `packages/mail/src/imap.ts:485–487` removes the source location even when MOVE returns no UID mapping. For an older message moved into a newly discovered mailbox, the windowed search at `:283–287` can miss its destination. Adding its snapshot-needed ID to `reconcile` then reaches the orphan deletion at `:250–259`. **Correction:** distinguish missing cached identity after MOVE from confirmed provider deletion; retain reconciliation work until bounded destination discovery resolves the UID identity.

4. **The specification overstates existing exact Undo.** `packages/db/src/actions.ts:194,207` and `packages/idb/src/mail.ts:774,779` compare/restore location through `placeOf`, which collapses three independent booleans. Starting with a trashed message, apply spam, then Undo: both states classify as trash, so restoration silently skips the changed spam flag. **Correction:** compare the complete saved flag tuple and derive provider steps from field differences. Add this public action/Undo regression, including the filter path through `sql-store.ts:352` / `idb/store.ts:787`.

5. **Rule 5 contradicts the proposed per-field final-step ownership.** For trash→archived Undo, `packages/db/src/actions.ts:153–158` generates `moveToInbox → archive`; Gmail’s `moveToInbox` establishes final trash/spam removal, while archive only removes INBOX (`packages/mail/src/gmail-api.ts:198–207`). The blanket statement that intermediate Undo steps cannot deliver location intent would strand trash/spam owners or incorrectly attach them to archive. **Correction:** prohibit acknowledgement only when the step is nonfinal **for that field**; specify the field masks and behavior when the second step fails.

6. **The Gmail drain lacks a finite, failure-isolated traversal contract.** Existing incremental reconciliation throws on one non-404 snapshot failure (`packages/mail/src/gmail-api.ts:675–680`), before any subsequently appended drain can run; `sync` also has separate full-sync returns (`:712–728`). The proposed `(afterMessageId, limit)` method bounds a batch, not the pass. **Correction:** define a captured eligibility boundary and continuation, isolate failed repair targets so healthy neighbors progress, and make repair reachable independently of unrelated delta failure. Preserve cursor advancement once skipped fields have durable obligations; do not require matching confirmation before accepting a genuinely fresh reversal.

### 1. Distinguish current ownership from every still-executable field effect

An intent version is not the complete delivery dependency graph. For each affected message/field, query **indexed active op_targets for that message/group**, and retain dependencies on surviving field-affecting predecessors. No operation may deliver a different latest generation merely because its desired boolean happens to match. However, **any settling predecessor that can affect that field advances the current generation's observation barrier**, even when its version no longer owns the desired value. Success, terminal failure, unknown settlement, cancellation and crash-recovery removal all update this dependency state atomically. Retry/auth/network park remains a live dependency; release before dispatch is still live queued work.

Concrete required RED: A=read running; B=unread queued; C=read cancels B without creating an op; an authoritative unread snapshot starts after C but before A settles, then arrives after A's success. C must not retire from this snapshot. C becomes snapshot-eligible only after **all surviving field-affecting predecessors** are settled; its barrier includes A's settlement epoch. A is recorded succeeded but does not acknowledge C. Reopen at every boundary. The same rule applies to a no-op reaffirmation and to a final owner whose earlier prerequisite has not settled. A benign repeated click with an existing matching owner stays a no-op.
