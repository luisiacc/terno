# W01 — durable Sent-copy recovery (2026-10-29)

This section supersedes the proposed r3 runtime below for this bounded slice; the old proposal is historical design material.

Request: “first durable Sent-copy failure/unknown-outcome recovery for supported SMTP, without resubmission.” “Sent APPEND errors are swallowed after submission. Preserve the current no-resend behavior while making missing-copy repair and partial acceptance discoverable. Classify rejected versus unknown APPEND outcomes; reconcile an unknown copy before replaying APPEND to avoid duplicate Sent copies.”

Investigation: IMAP `send()` catches all APPEND failures and returns success. SMTP and backend acceptance latches must precede optional normalization/storage. Existing successful operations contain no proof of an IMAP copy. Plan26 T01 remains authoritative for no automatic SMTP replay; Plan45 requires reconciliation of uncertain mutations. Plan68 folder schema stays intact.

Design: new sends to IMAP accounts with appendToSent reserve a fixed receipt and worst-case 25MiB wire budget inside queueSend before draft deletion. At most 128 receipts and 256MiB reserved wire globally; account attachment plus wire usage stays at 256MiB. At most 3000 recipient occurrences. A private header separates submission (pending/accepted) from copy (pending/rejected/unknown/saved), with exact mailbox/UID identity when available. Wire bytes are immutable, chunked at the existing 48KiB boundary and cold in IDB; actual size replaces reservation before SMTP. Before APPEND, persist unknown; only a tagged rejection proves rejected, and only a positive APPEND result or exact-byte reconciliation proves saved. Acceptance is latched before any optional work, persisted before APPEND, and can never authorize SMTP retry. Interrupted pending submissions retain existing unknown-send semantics. Legacy operations have no invented receipt.

Recovery is deliberate through a narrow renderer RPC and lazy account-settings list. Reconcile the recorded Sent mailbox by the original Message-ID and exact stored bytes before any repair APPEND; a collision/multiple candidate/search failure remains unknown. Repair owns an account lifetime/drain slot, serializes per receipt and never invokes SMTP. No polling, startup repair or retry timers. Fixed English/Spanish warnings retain partial-recipient information. Explicit Forget removes bytes in bounded units and frees quota only when removed. Receipts are private local history, excluded from application export; normal full-store image paths preserve the new tables.

Tests: real SMTP accepted counts, real IMAP rejection and lost acknowledgement, exact copy bytes and identity, durable SQL/IDB reopen, pre-draft quota refusal, immutable wire, replay fences, interrupted repair, and existing T01/direct callers. Targeted package types/lint only; affected UI e2e with inspected light/dark screenshots and accessibility; one affected hot-path perf file. No production builds or full gates under this worker's course correction.

Out of scope: recipient ledger UI, Gmail-managed Sent, Outlook, automatic uncertain SMTP retry, archive adoption, folder-pipeline changes and unrelated provider work.

#### Actual primitive and private lifetime
