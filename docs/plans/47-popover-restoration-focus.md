## Candidate design, before source critique

Fix the underlying deferred restoration in the pinned dependency, rather than add a sign-in-specific focus fight. Carry a pnpm patch for both ESM and CJS FloatingFocusManager files of exact @base-ui/react 1.9.0. At the start of its existing focusout handler, a non-null relatedTarget cancels the existing restoreFocusFrame and advances a private restoration generation. Capture that generation before immediate popup restoration and require it still current with open/connected state before deferred focus. Invalidate old restoration at the existing initial-focus layout effect on open/disabled/floating lifetime changes. A later focus choice then invalidates that stale attempt, including choices within the scheduler's already-detached batch or immediate-focus reentrancy, while the already-owned immediate popup restoration remains intact. If the newly focused element is itself removed, its own queued restoration may schedule a new frame under the existing logic. No new timer, polling, event listener, app field, public API, eager UI, copy, schema or mail-provider work. Existing library mount cleanup and AnimationFrame cancellation own lifetime.

The patch is preferred to overriding Popup focus events, re-focusing the password on account updates, preserving deleted account DOM, changing initialFocus, dependency upgrades or private Base UI store probing. The public Popup API does not expose restoreFocus; initial/finalFocus address different transitions.
