## 1. What exists

- Plans 10, 12 and 13 added English literals (diagnostics, the unread filter, the docked snack); their Spanish wording is in `/tmp/unica-scratch/i18n-new-strings.md`.
- Dates and numbers: `Intl.DateTimeFormat("es")` and `toLocaleString("es-MX")` hard-coded in ~15 places; one `"en-US"` in the list header.
- `index.html` and the print document say `lang="es"`; the web manifest says `lang: "es"`.
- Playwright runs with `locale: "es-MX"` in both configs; `playwright.web.config.ts` has fixed ports 5181/5182.
- Settings are one JSON value (`settings.app`) in the store's settings table, the same code for SQLite and IndexedDB (`packages/backend/src/settings.ts`): a new field needs no migration in either store.
- Main learns policy from the backend (`{ type: "policy" }` on the parent port) and persists appearance in `userData/appearance.json` for the next window's first frame.

## 2. Design

### The module: `packages/i18n` (`@terno/i18n`)

No dependency, no React. ~200 lines.

```
packages/i18n/src/
  index.ts          t(), rich(), setLocale(), getLocale(), resolveLocale(), formatters
  format.ts         the ICU-lite compiler/formatter
  types.ts          Key, Params<K>, LocaleCheck<T>
  locales/en.ts     the source of truth (bundled)
  locales/es.ts     typed against en
  locales/index.ts  the registry: one line per language
```

- **Flat keys**, dot-prefixed by area: `"list.empty.title"`, `"reader.archive"`, `"common.cancel"`. Flat keeps the types cheap (one `keyof`), makes grep work, and makes a locale file a plain list a translator can read top to bottom. Sections are separated by `// ── area` comments.
- **Messages** are strings with:
  - interpolation `{name}`;
  - plurals `{count, plural, =0 {…} one {# day} other {# days}}` (`#` is the number formatted for the locale; categories from `Intl.PluralRules`, a missing category falls back to `other`, so Spanish's `many` needs no branch);
  - select `{host, select, mac {this Mac} other {this browser}}`;
  - rich tags `<b>…</b>`, `<link>…</link>` for `rich()`, rendered by callbacks (no `dangerouslySetInnerHTML`).
- **Types.** `en` is `as const`. `Params<K>` is extracted from the English message with template literal types: a `{name}` gives `name: string | number`, a `{count, plural, …}` gives `count: number`, a select gives `string`, a `<tag>` gives a renderer (only in `rich`). `t(key)` compiles only when the message has no params; otherwise `t(key, params)` with exactly those params.
- **Locale files are checked against `en`:** `es.ts` ends with a `LocaleCheck<typeof es>` assignment where every `en` key is required, an extra key is typed `never`, and a leaf whose placeholder set differs is typed as an error string (`"✗ placeholders must be: {count} {name}"`). A missing key, an extra key or a renamed placeholder fails `pnpm typecheck`.
- **Runtime.** `t()` looks the key up in the active catalog (falling back to `en`), returns plain strings directly, and compiles a message with `{` or `<` once into a cached part list (Map lookup after the first call: O(1)). No subscription, no hook, no re-render.
- **Registry** (`locales/index.ts`):
  ```ts
  export const LOCALES = {
    en: { name: "English", load: async () => en },
    es: { name: "Español", load: () => import("./es").then((m) => m.default) },
  } as const;
  ```
  Adding a language is a new `locales/xx.ts` plus one line here. `LocaleId = keyof typeof LOCALES`; the settings enum is derived from it.
- **Resolution.** `resolveLocale(setting, systemLanguages)`: an explicit `"en"`/`"es"` wins; `"system"` takes the first system language whose base language is registered (`es-MX` → `es`), else English. English is the fallback for anything missing.
- **Formatters** in the package, all using the active locale: `formatNumber`, `formatList` (`Intl.ListFormat`), `formatRelative` (`Intl.RelativeTimeFormat`), and the BCP 47 tag (`en-US`, `es-MX`) the date helpers use.

### Loading and switching in the renderer

- `apps/web/src/lib/i18n.ts` holds the renderer side: `initLocale()` before the first render, `applyLanguage(setting)` after bootstrap and on every change, `richT()` (rich parts with React keys).
- **First frame in the right language:** the last resolved locale and setting are cached in `localStorage` (`terno:locale`), written whenever they change (like `terno:appearance`). `main.tsx` awaits `initLocale()` before `createRoot().render()`: English is synchronous; Spanish awaits its chunk (local file on desktop, precached by the service worker on the web: a few ms). No cache yet: `"system"` from `navigator.languages`.
- Only the active locale is loaded: `es.ts` is its own chunk (a dynamic import), English is in the entry chunk. A build check asserts the entry chunk doesn't contain a Spanish catalog marker.
- **Live switch without a reload:** `applyLanguage` loads the catalog, calls `setLocale`, sets `<html lang>`, writes the cache, then bumps a `localeEpoch` in the app store; `App` renders its tree under `key={localeEpoch}`, so everything re-renders once with the new strings and date formats (the React Compiler memoizes components, so a plain re-render from the root wouldn't reach them; a keyed remount does). Nothing is lost: navigation, selection, open dialog, settings tab, drafts, the unread filter and the snack are in stores, not component state. During the remount motion is suspended for two frames (no dialog re-entrance animation), and focus goes back to the Language control.
- Strings are always produced at render or call time, never at module load (a module-level `const LABEL = t(...)` would freeze the first locale). The source scan test flags `t(` at module top level.

### The setting

- `AppSettings.language: "system" | LocaleId`, default `"system"`; zod `z.enum(["system", ...LOCALE_IDS])`; `DEFAULT_SETTINGS.language = "system"`. Imports and exports carry it like the other general settings.
- Ajustes/Settings → General, first group, a "Language" row: a `Select` with "System (English)" / "English" / "Español". The option names are each language's own name (never translated); "System" is translated and shows what it resolves to.
- ⌘K: "Language: English/Español" commands are out of scope (one setting row is enough).

### Desktop main

- The backend's policy message grows `language`; main resolves it with `app.getPreferredSystemLanguages()` (falling back to `app.getLocale()`), calls `setLocale`, persists `{ language }` in `userData/locale.json` (debounced like appearance), and rebuilds the menu when the resolved locale changed.
- At startup (before the backend reports) main reads `locale.json`; without one it resolves `"system"`. `profile.ts`'s error boxes run before that and use the system language.
- **The menu** is built from the catalog: Archivo/File, Edit, View, Window, Help, with explicit labels on role items (Electron's own role labels are English-only, so a Spanish menu sets every label; the role keeps its behavior). Menu items use title case in English (macOS HIG), sentence case in Spanish as today.
- Dialogs (diagnostics export, save panels for PDF and diagnostics, error boxes), the PDF footer's "(no subject)", the PDF name fallback, the export README and the diagnostics file names come from the catalog in main.
- Notifications: main shows none today (nothing to do).

### Backend

- User-facing errors and messages use the same `t()`: one locale per backend process, set from `settings.language` and the host's system languages (main passes `systemLanguages` in `init`; the web worker reads `navigator.languages`; backend-dev takes an option, default English). It is set at start and again on every settings change.
- Not translated: log codes, developer-only errors ("Backend needs a store or a dbPath"), RPC error codes, MCP tool descriptions (read by agents, English), and mock-data mail content.

### Dates and numbers

- `lib/format.ts` builds its `Intl.DateTimeFormat`s for the active locale and rebuilds them when the locale changes (a module cache keyed by locale; rebuilt in `setLocale`'s listener).
- English list dates, like Mail: "9:34 AM" today, "Yesterday", "Oct 22" this year, "Oct 22, 2024" before; full dates "Wed, Oct 22, 2025, 9:34 AM". Spanish keeps today's formats exactly ("09:34", "22 oct", "22 oct 2024", no "Ayer"): the formats are a small per-locale table in `format.ts`, so a language chooses its own.
- Every `toLocaleString("es-MX")`/`"en-US"` becomes `formatNumber()`.
- `<html lang>`, the print document's `lang`, and the web manifest's `lang` follow the locale (the manifest says `en`; it's static).

### Copy

- English: natural, concise, Apple-like. Sentence case for labels, buttons and titles; title case only for menu items. Curly quotes and apostrophes (’ “ ”), the ellipsis character (…), "Settings → General" with the arrow.
- Spanish: today's wording exactly (it has been reviewed), plus the translations of plans 10/12/13 from the scratch file.
- Brand and product names stay as they are (Terno, Gmail, Ollama, Claude Code); keyboard keys too.

### What gets translated

Every user-visible string: UI text, `aria-label`, `title`, tooltips, placeholders, empty states, errors shown to users, snack messages, the print sheet and the print document's labels (From/To/Cc/Date/Attachments), the PDF footer, diagnostics surfaces and the export README, menus, desktop dialogs and save panels, the web's storage/onboarding/gate screens, reply and forward headers written into drafts ("On … wrote:", "Forwarded message"). Not translated: log codes, developer-only messages, test fixtures' mail content, search operators (`from:`, `de:` both keep working).

## 4. Tests

- **Unit (`packages/i18n`):** interpolation; plurals in en and es (0, 1, 2, 1 000 000 → `many` falls back to `other`); `=0`; select; `#` formatting; rich tags with callbacks, nested text, unknown tags left as text; missing key falls back to English; `resolveLocale` (`system` + `["es-MX"]` → es, `["fr-FR","es"]` → es, `["fr"]` → en, explicit wins); every `es` message compiles and uses the same params as `en` (runtime mirror of the type check); a type test (`// @ts-expect-error`) that a missing param, an extra param and a wrong key don't compile, and a fixture locale with a missing key / extra key / renamed placeholder fails `LocaleCheck`.
- **Source scan** (`packages/i18n/src/scan.test.ts`): walks `apps/*/src` and `packages/*/src` (not tests, fixtures, mock-data, e2e) with the TypeScript parser (`typescript` is already a dev dependency) and fails on JSX text with letters, and string literals with letters in `aria-label`, `title`, `placeholder`, `alt`, `label` props, `snack*()`/`toast` first arguments, `throw new RpcError/SettingsError/AiError(…, "…")` messages; and on `t(` at module top level. A short, commented allowlist (brand names, keys like "⌘", "Terno", "Gmail", "Cc") instead of per-file exemptions.
- **e2e:** the suite runs with `locale: "en-US"` (System → English). Assertions move to English; brittle text locators become test ids or roles where they were brittle. Baselines are regenerated deliberately and inspected.
- **e2e `i18n.spec.ts`:** switch to Español in Settings → General → list header, reader toolbar tooltips, settings tabs, palette, a snack, the print sheet, diagnostics show Spanish; dates are Spanish ("22 oct"); switching back restores English without a reload (a `window.__loadMarker` survives). A Spanish walk over every settings tab and main surface: for every visible text node, it must not equal an `en` value whose `es` differs (the catalogs are imported into the spec).
- **Visual:** baselines in English; Spanish baselines for the densest screens (main window, settings General and Appearance, print sheet) to catch overflow.
- **Desktop smoke:** the menu bar is English by default (`Menu.getApplicationMenu()` labels through the test hook), Spanish after the setting changes, without a restart.
- **Perf:** `test:ui-perf` and the startup smoke unchanged; `t()` microbench in the unit suite (≤ 1 µs per call warm on a plural message).

## 5. Performance and resources

- English adds nothing to load: the catalog is in the entry chunk (it replaces the literals). Spanish is one lazy chunk (~40 KB raw, ~12 KB gzip), loaded only when Spanish is active.
- `t()` is a Map lookup plus, for messages with params, a walk over precompiled parts. No React subscription.
- A locale switch costs one remount (a user action, rare).
- Main and the backend bundle both catalogs (esbuild CJS inlines dynamic imports): a few tens of KB of strings, no runtime cost unless used.

## 6. Out of scope

- Right-to-left layouts, per-account languages, translating mail.
- macOS-provided menu items (Services, Start Dictation, Emoji & Symbols) follow the system language and the bundle's localizations, not the setting.
- Search operators keep their Spanish aliases; no new aliases per language.

## 7. Revisions after the Codex review

Codex's 12 points (`/tmp/unica-scratch/plan-14-codex.txt`) and what changed. Where this section and §2–§5 disagree, this section wins.

1. **Keyed remount loses state.** Kept, deliberately, with what it loses made explicit and the rest restored. The alternative (`useT()` in every component) only works if every helper that formats text during render (dates, view labels, reasons) also takes the locale, since the React Compiler memoizes those calls on their other inputs; one forgotten helper is a stale string, and the leak test would have to find it. A language change is rare and made from Settings. Survives (stores): navigation, selection and checks, open dialog and tab, drafts (autosaved in `lib/drafts`), unread filter, undo, the snack. Restored: the list's and the reader's scroll offsets, focus on the Language control when the change came from it. Resets: which messages of the open conversation are expanded, uncommitted typing (settings fields commit on blur, before the select opens). Motion is suspended for two frames. The e2e asserts the survivors.
2. **ICU parsing.** The grammar is restricted: flat `{name}` placeholders, plurals as objects with one full sentence per category (`{ one: "# conversation", other: "# conversations" }`, `=0`/`=1` allowed, `#` the formatted count), flat `<tag>…</tag>` rich text, no `select` (two keys instead). No nesting, so the type-level and runtime parsers are a few lines each and agree.
3. **`LocaleCheck`.** `es.ts` is `as const` and ends with `export default es satisfies LocaleCheck<typeof es>`; the mapped type is over English's keys (missing → error) plus `never` for extras. Kinds are compared (a plural must stay a plural), placeholders and tags too; a mismatch's error type quotes the English message. Type tests with `@ts-expect-error` cover a missing key, an extra key, a renamed placeholder, a plural turned into a string, wrong/missing/extra params. `rich()` only accepts keys with tags; `t()` only keys without (a plain copy of a rich message is its own key).
4. **First frame.** The cache holds the *setting*, re-resolved at start against today's `navigator.languages`. Default "system" stays: the request is English unless the system is Spanish. A missing cache (first run, cleared storage) resolves "system" until bootstrap, then the stored setting wins; a failed read or chunk load falls back to English and renders anyway.
5. **One locale per backend process.** Removed: **the backend has no locale.** It produces descriptors (`L(key, params)` → `{ key, params, message }` with `message` in English): user-facing errors carry `i18n: { key, params }`, `toErrorPayload` puts it on the wire, the RPC client keeps it, and the renderer's connection sets `error.message = t(key, params)`. Every `e.message` in the UI then shows the user's language. backend-dev, the worker and the utility process need nothing.
6. **Settings plumbing.** `language` goes into `AppSettings`, the patch schema, `DEFAULT_SETTINGS`, read normalization (unknown → "system"), `GENERAL_KEYS` in `import.ts`; `settings.update` and `importMailbox()` publish the policy (now with `language`) when it changes. The renderer applies the language from a zustand subscription on `settings.language`, which catches every path that sets settings (bootstrap, Settings, imports, the web's storage carry-over).
7. **Ordering.** `applyLanguage` is serialized by a sequence number (a slower load that finishes after a newer choice is dropped), catalog loads are deduplicated, and publication is one step after loading (`setLocale`, `<html lang>`, cache, remount). `languagechange` re-applies while the setting is "system". Focus moves only when the change came from the Language control.
8. **Strings already stored.** The categorization reasons, persisted in `explain_json` in both stores, become descriptors `{ k, p }` rendered by the reader; old rows keep their string reasons and show them as they are. Snack text and the "select all" scope label are transient (seconds) and keep their language until replaced; reply/forward headers become draft content and never change. Provider error text from servers is passed through as is.
9. **Loading and perf.** The service worker precaches every chunk of a build, so web users download the Spanish chunk once (~12 KB gzip) without evaluating it; that is accepted (it makes a switch work offline) and documented. `Intl` formatters and compiled messages are cached per locale. The `t()` timing gate moves to the perf project (`packages/i18n/src/t.perf.test.ts`); the entry chunk and worker sizes are reported before/after.
10. **Menus and readiness.** App, Edit and Window menus are expanded templates (each item keeps its `role`, gets a `label`), File/View/Help as before. `app.getPreferredSystemLanguages()` is only called after `ready`; before it (`prepareProfile`'s error boxes) main uses `locale.json` or English. The diagnostics README is built at call time; archive entry names stay fixed.
11. **Source scan.** Written as a module (`packages/i18n/scripts/scan.ts`, run by `scan.test.ts`) using `@babel/parser` (TypeScript 7's npm package has no stable JS parser API). It checks JSX text; `aria-label`, `title`, `placeholder`, `alt`, `label`, `hint`, `description`, `detail`, `message`, `heading` attributes and object properties; first arguments of `snack*()`; message arguments of `SettingsError`/`AiError`/`NetworkPolicyError` (first) and `RpcError` (second); template literals with static letters in those positions; and `t(` evaluated at module load (calls inside functions, arrow bodies and class members are fine). It has its own fixture tests for true and false positives (shortcuts like `G I`, `⌘K`, brand names, identifiers, URLs, CSS classes). It is a guard against regressions, not a proof of completeness; the Spanish e2e walk is the second net.
12. **e2e evidence.** The switch test asserts the survivors of §7.1 (selection, open dialog and tab, a draft's text, list scroll offset, undo after the switch) instead of only "no reload". The Spanish walk checks visible text nodes *and* `aria-label`/`title`/`placeholder`, skips mail content (rows' from/subject/snippet, the reader's subject and bodies, category and account names via `data-mail-content`), and flags a node that equals an `en` value whose `es` differs or contains the static part (≥ 2 words) of an English template. The web suite gets a test that Spanish survives a reload and shows on the first frame; the desktop smoke checks nested menu items (Edit → Undo) in both languages. `listDate` unit tests cover midnight, yesterday across DST, and the year boundary in both languages.

## 8. As shipped

### Departures from the plan

- **Learned filters** are named in the user's language by the renderer (`learning.accept` takes an optional `name`; English without one); existing filters keep their names. Names are capped at the 120 characters `filters.save` and exports take.
- **A placeholder can be a message** (`keyRef(key)`): provider labels like "Custom", "Offline demo" and "Off" travel inside backend error descriptors and render in the language of the message they fill.
- **Theme names:** Terno's own two display through the catalog ("Terno Light"/"Terno Dark", "Terno claro"/"Terno oscuro"); ids and product-named themes are unchanged.
- **Filter-rule validation** keeps English messages (the AI repair loop and agents read them) and carries the key in the issue's params; the filter builder shows the key.
- **The RPC client's own failures** (not connected, closed, timed out) are catalog messages too.
- **Select none / Deselect:** English gives the two shortcuts distinct names; Spanish keeps "Deseleccionar" for both, as before.
- macOS-provided menu items (the contents of Services, Start Dictation, Emoji & Symbols) follow the system, as planned.

### Bugs found by the tests

- **The React Compiler and module state:** the first `LocaleRoot` read a module variable after clearing it (the compiled code re-read the binding instead of the local alias): a TypeError on every switch that took the settings sheet down. The restore moved out of the component.
- **Re-mounting an open Base UI select** crashes it: a choice in the open list waits for `onOpenChangeComplete`.
- **Category order buttons:** "Move “Facturas” up" didn't contain the visible "Move up" (axe: label in name); now "Move up “Facturas”".
- **The narrow print sheet** scrolled a focused control under its sticky buttons (exposed by the English labels; also true at 200% zoom).
- The web `updates.spec.ts` was always skipped under `WEB_PORT`: it looked for the default build directory.

### After the Codex code review (4 findings, all fixed; `/tmp/unica-scratch/i18n-14/review.out`)

1. A failed language save never rolled back (the settings `update` swallows errors). `commitLanguage` saves with `quiet`, says why, and returns to the previous language unless a newer choice was made (unit tests).
2. Typing on the closed Language control (typeahead) only staged the choice. It applies at once now; only a choice in the open list waits for the list to close (e2e). Fixing it exposed another bug: answers to earlier choices arriving while a newer one saved switched the app back and forth. The follower ignores settings answers while this window's own choices are saving (a unit test that fails without it), and the settings sheet takes no initial focus during a switch, so focus stays on the control.
3. A learned filter for a long list id produced a name over the contract's limit and couldn't be accepted (the banner swallowed the error): names are capped, and the banner reports failures (unit test).
4. `formatNumber` with options built an `Intl.NumberFormat` per call (~15 µs; every attachment size): cached per locale, gated in the perf project (fails without the cache).

### Measured

- `t()`: 0.03 µs plain, 0.8 µs plural with a formatted count; `formatNumber` with options 0.5 µs (perf project, both locales).
- Entry chunk: 469 KB raw / 151.7 KB gzip, against 446 / 148.9 KB at the infra commit (catalog in, literals out: +2.8 KB gzip). The Spanish chunk is 72 KB raw / 20 KB gzip, loaded only when Spanish is active (precached by the web's service worker).
- `test:ui-perf`: all 17 within budget (j 2.7 ms p95, search 18 ms, theme switch 35 ms, inline reply first frame 17 ms, print document 9.6 ms). `test:perf`: 109 passed.
