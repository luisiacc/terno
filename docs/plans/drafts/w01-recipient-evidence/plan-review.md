1. **Keep submission certainty separate from recipient results.** A resolved SMTP send with malformed recipient lists becomes “all unknown,” but submission is still accepted. Specify an independent accepted/ambiguous submission discriminator and preserve the existing latch before fallible normalization. Use it for both manual retry refusal and the final backend dispatch fence, including `appendToSent=false`. Checking for an individual accepted recipient would permit duplicates. See [SMTP’s current acceptance ordering](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/mail/src/smtp.ts:89).

2. **Resolve “first evidence is immutable” across retryable attempts.** All-recipient temporary rejection and explicit DATA 4xx currently permit retry. If that attempt publishes immutable rejected evidence, a later successful attempt cannot truthfully replace it. Specify which outcomes may establish the operation’s immutable result, and distinguish RCPT acceptance from final DATA acceptance. Add temporary-refusal → successful-attempt coverage. See [SMTP classification](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/mail/src/smtp.ts:33) and [operation retry behavior](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/db/src/repos.ts:527).

3. **Bound total evidence storage, not just one send.** Operation history retains successful sends, and IDB loads `ops` eagerly. Adding up to 3000 addresses to every historical target grows disk and startup memory indefinitely; the Sent-copy quota does not cover this JSON. Define aggregate byte/count admission or bounded retention, preserving a compact replay prohibition when detailed evidence is removed. Also bound provider-list inspection and serialized warning size. See [IDB’s eager operation table](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/idb/src/schema.ts:58).

4. **Correct the claim that `messageIds` are immutable.** Both stores prune deleted messages from running sends’ targets. Publishing evidence from a captured target snapshot could restore deleted IDs; SQLite may subsequently reuse them. Require an atomic merge into the *current* target, preserving pruning and unrelated fields. Test deletion during submission followed by completion and reopen. See [SQL target pruning](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/db/src/repos.ts:490) and [IDB target pruning](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/idb/src/mail.ts:1613).

5. **Define “canonical envelope” against the installed transport.** [`envelopeOf`](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/mail/src/compose.ts:71) supplies addresses that Nodemailer further normalizes and deduplicates. Its domain normalization also differs for SMTPUTF8 local parts. Specify occurrence-to-envelope matching for Unicode/punycode equivalents, domain case and cross-field duplicates. Derive evidence without rewriting payload, sealed wire or the existing submitted envelope merely to simplify matching.

6. **Make operation evidence authoritative through Sent-copy transitions.** Current projections prefer receipt warnings, while copy recording and `markSent` can replace `last_error` from the receipt. Updating only `complete`/`markUnknown` leaves repair, manual resolution and receipt reclamation able to hide recipient outcomes. Require evidence-derived flags/details across those paths, with local errors retained separately. APPEND success must never upgrade recipient submission results. See [warning projection and copy recording](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/db/src/sql-store.ts:638).

7. **Narrow or fix the reopen-discoverability promise.** `ops.recent` excludes succeeded operations after one hour; `ops.list` returns only 100 entries. The renderer displays live operation events and does not restore these warnings on startup. Consequently, durable partial acceptance with `appendToSent=false` can become inaccessible through the proposed public surface. Define bounded retrieval of outstanding recipient warnings, or explicitly qualify this as RPC-only evidence with limited discovery. See [recent filtering](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/db/src/repos.ts:601) and [renderer notifications](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/apps/web/src/lib/boot.ts:100).

8. **Qualify fallback guarantees at real transaction boundaries.** Distinguish rollback, commit followed by caller rejection, and uncertain IDB persistence. IDB can close the adapter after an uncertain write, making same-process fallback impossible. Require native SQL/IDB fault cases and reopen assertions: preserve any committed evidence, leave unproved recipients unknown, and never redispatch SMTP. Mocked method rejection alone cannot qualify this guarantee. See [IDB persistence failure handling](/Users/Luis/.t3/worktrees/emailclient/t3-84b6de0a/packages/idb/src/store.ts:355).

9. **Place recipient admission before draft deletion.** “Before transport” allows validation only after `queueSend` has consumed the draft. RPC validation bounds normal callers, but direct store callers bypass it, and the current receipt-specific cap excludes `appendToSent=false`. Require transactional admission in both `queueSend` adapters, plus conservative dispatch validation for legacy queued payloads. Over-limit refusal must preserve authored work without truncating recipients or changing captured bytes.
