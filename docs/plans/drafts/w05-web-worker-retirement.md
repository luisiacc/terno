# W05/A09 Web worker physical retirement

## Request

“does replacement/retirement of a Web backend worker prove old physical native requests/body ownership are gone BEFORE new owner/account work can safely proceed, including an old worker ignoring RPC cancellation?”

Implementation sub-agent, no children; expected and actual base 41e7fd760f0dc8d1fa48ab12661be5e1dd0ce493. Own Web connect/worker lifecycle and dedicated dev-only tests/config/docs only. Preserve W03 snapshots/promotions/yields, W02 Undo, W05 admission, Plan87 schema/reminders, all user and held work. Root owns integration and worklist. No release gates or production build.

## Existing

connect.ts holds both terno-backend and unica-backend Web Locks in the page before spawning a backend worker. Handoff saves drafts, sends close, waits for closed or ten seconds, terminates the native Worker, then releases leadership. Fatal termination also precedes release. backend.worker.ts stops backend, pauses OPFS SAH pool and posts closed. OPFS itself excludes simultaneous sync access handles. S55 already qualifies queued-send/assets across normal reopen and idle/auth behavior; it does not witness native fetch terminal. Plan62's historical retain-until-closed proposal is stronger than shipped behavior; this task qualifies forced retirement explicitly rather than adopting that proposal silently. Plans43/62/71 and current Plan87 constraints apply.

## Design

First qualify existing protection, no invented registry/leases. Dedicated Vite serve-only instrumentation injects an independent native streaming fetch and OPFS sync handle into the actual backend worker. Source identities are per worker. A synthetic owned loopback server observes request start and response close. Test instrumentation holds or ignores close without replacing clocks, terminate or fetch. Actual Chromium worker close event, remote stream closure, reacquisition of the exact OPFS handle and actual replacement backend RPC distinguish physical from logical retirement. Native stream is intentionally independent of BackendCore cancellation. Test graceful, stuck/late close timeout, fatal termination, normal reload and competing tab. Pin pending operation/draft/assets where practical without reproducing S55's full UI matrix. No new provider traffic; intercept external routes before app/Backend construction, reject unexpected routes.

## Tests and controls

Negative oracle must fail when old physical terminal/source identities are absent or duplicate starts occur. Record native close vs remote close ordering honestly: Worker.terminate returns void, remote observation can lag local worker death; no arbitrary remote-server completion guarantee.
