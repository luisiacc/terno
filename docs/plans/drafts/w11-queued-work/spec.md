# W11 S55 browser queued work

Request: “S55 needs work: idle after healthy sync/auth refusal has no spinning timers or unexpected network except intentional liveness; browser reload/expiry preserves queued work while token reacquisition is pending.” The full task also requires a real OPFS worker/store reopen, immutable send and attachment, controls for refusal and ownership, and exactly one submission after same-account reauthentication.

Existing: Web leadership holds `terno-backend` and legacy Web Locks; a waiting tab polls for takeover liveness. Browser Google tokens live in the worker and are reacquired via GIS; no server refresh token exists. `compose.send` commits to the store before kicking the worker; `ops.list` exposes status. Plan 62 records W05 cooldown and known token503/folders429 backlogs. Plans 65 and 69 describe durable send and storage, without granting changes there. The W12 GIS harness boots a real worker with OPFS and stubs provider requests but does not reopen the store.

Design: dedicated dev-only Vite/Playwright project with a fresh synthetic mailbox, exact Google endpoints and external traffic blocked. Queue via public UI/RPC with the worker offline before transport; reopen via reload, check the same op, payload and attachment through public reads, deny GIS and confirm no send or charged retry, then reauthenticate the same account and observe one real stubbed Gmail submission and no repeat after another reload. Include a competing tab lock control and an idle observation distinguishing expected lock liveness. Avoid test-only persistence or provider bypass; if public seams cannot observe a guarantee, document the limit rather than simulate it. Product changes only for demonstrated owned-seam bugs.

Tests: meaningful baseline controls before any fix; browser test plus touched module/direct caller tests and package type/lint as applicable. UI-only changes require locale, accessibility, keyboard and inspected light/dark evidence. No UI change is planned. Perf: no hot path change planned; bound observed requests and idle behavior. Out of scope: backend/core, stores, draft helpers, provider implementations, W05 503/429 backlogs, production builds, real GIS and process-crash claims.

## Revisions after the Codex review

The native Sol/high read-only critique returned 11 points. Use a newly created non-demo Gmail account, acknowledged offline RPC, op/thread IDs, public message/attachment reads and decoded submission, with strict method/path stubs. Track old/new worker lifetimes, both locks and wrong-account/refusal controls. Reauthenticate after the final reload to make the duplicate fence meaningful. Expiry is a separate same-worker case; page clock is not a worker clock. Idle evidence must distinguish the 120-second sync, five-minute cache tuning, ten-minute categorizer and follower lock liveness from spin, with a stated observation window. Public message reads omit Bcc, so MIME is the end-to-end semantic oracle, not proof of private byte-for-byte op serialization. Targeted checks follow the user's explicit qualification scope; broader AGENTS release gates remain unrun. Separate native Standards+Spec code review is required after the coherent slice.

## Qualification so far

The dedicated dev-only test passed 2/2 on real Chromium worker and OPFS. It uses a 64-second real token lifetime, crossing the existing 60-second safety margin in the same worker, then restores a valid token while offline before reload. It checks the same queued op, message and attachment, popup refusal, wrong identity, one decoded Gmail submission and a reauthenticated later reload. A competing tab and a legacy-only lock holder exercise ownership. A three-second auth-blocked interval observes no provider requests and unchanged attempts; it does not instrument worker timer callbacks or prove absence of all CPU spin. Healthy long-period timer ownership is not qualified. Initial characterization failed on test assumptions (`done` versus `succeeded`, raw versus base64 MIME, invalid sync reason, unstubbed GIS and an icon navigation); these were harness errors, not product REDs. No production changes or simulated persistence.

Scoped web typecheck and strict lint passed; no full gates or production builds were run per task scope. The package's standard install setup ran automatically. Plan review raised the broader AGENTS checks; the user's more specific scope controls this qualification and full release gates remain pending.
