# W11 S55 browser queued work

Request: “S55 needs work: idle after healthy sync/auth refusal has no spinning timers or unexpected network except intentional liveness; browser reload/expiry preserves queued work while token reacquisition is pending.” The full task also requires a real OPFS worker/store reopen, immutable send and attachment, controls for refusal and ownership, and exactly one submission after same-account reauthentication.

Existing: Web leadership holds `terno-backend` and legacy Web Locks; a waiting tab polls for takeover liveness. Browser Google tokens live in the worker and are reacquired via GIS; no server refresh token exists. `compose.send` commits to the store before kicking the worker; `ops.list` exposes status. Plan 62 records W05 cooldown and known token503/folders429 backlogs. Plans 65 and 69 describe durable send and storage, without granting changes there. The W12 GIS harness boots a real worker with OPFS and stubs provider requests but does not reopen the store.

Design: dedicated dev-only Vite/Playwright project with a fresh synthetic mailbox, exact Google endpoints and external traffic blocked. Queue via public UI/RPC with the worker offline before transport; reopen via reload, check the same op, payload and attachment through public reads, deny GIS and confirm no send or charged retry, then reauthenticate the same account and observe one real stubbed Gmail submission and no repeat after another reload. Include a competing tab lock control and an idle observation distinguishing expected lock liveness. Avoid test-only persistence or provider bypass; if public seams cannot observe a guarantee, document the limit rather than simulate it. Product changes only for demonstrated owned-seam bugs.

Tests: meaningful baseline controls before any fix; browser test plus touched module/direct caller tests and package type/lint as applicable. UI-only changes require locale, accessibility, keyboard and inspected light/dark evidence. No UI change is planned. Perf: no hot path change planned; bound observed requests and idle behavior. Out of scope: backend/core, stores, draft helpers, provider implementations, W05 503/429 backlogs, production builds, real GIS and process-crash claims.

## W11 idle ownership continuation

The user authorized bounded test-only timer observation, retaining native receiver, handles and cancellation, with no scheduler/clock replacement. A dedicated serve-only Vite transform inserts a first import into the actual backend worker; the probe forwards `this` via `Reflect.apply`, preserves native handles and callbacks, and reports only aggregate starts, callbacks, clears and pending delay classes. Invalid receiver controls for both set and clear throw as native Chromium does. The normal dev worker response contains no probe reference and standard web Playwright discovery lists 51 tests in nine files without this dev-only test; no production entry or RPC changed. The probe's overhead is not performance evidence.

After successful synthetic Gmail sync and again with a queued auth-blocked operation, five-second real-worker windows allow at most two short starts/callbacks, three total starts/callbacks and bounded pending growth; no Google requests are allowed. Both observed zero starts/callbacks, with three legitimate intervals pending at 120000, 300000 and 600000 ms (sync, cache tuning, categorizer); auth-blocked additionally had one non-short pending timer. A separate five-second window follows popup refusal. These windows bound observed spin, not every future deadline or whole-system performance. The test never fakes clock or worker/store. A controlled recursive 10ms retry mutation failed the same oracle with 23 short starts in 300ms (expected <=2); it was stopped, its handle cleared, and the retained control asserts that the oracle rejects it. Browser cases passed 2/2 after restoration on local main rebase. Healthy and auth windows exercise the real callback ownership in addition to network and unchanged op attempts. The former partial qualification caveat above is superseded for these bounded windows; broader release and W05 503/429 backlogs remain open.
