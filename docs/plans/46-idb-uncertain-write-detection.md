## Exact candidate protocol

Use one reserved private key in existing meta, fixed-shape and content-free. Any present value, including malformed/unknown, is dirty. Never clear dirty on reopen. No timestamps/history/mail identifiers/log content. Existing independent writers remain unsupported; use existing single leader/Web Locks and same-transaction guard to prevent a participating writer from overwriting dirtiness, without claiming cross-instance memory coherence.

Every nonempty persist and writeMeta transaction includes meta and the original durability. Attach actual complete/abort observers first. In native request callbacks, with no awaits/timers: guard-get; if clean, marker-put; only marker SUCCESS enqueues body puts/deletes. Guard every callback/enqueue. Count every enqueued body request and latch its first error before default abort. Enqueue marker-delete only after the body enqueue loop finished normally and ALL body request successes occurred. Never clear after any error or incomplete enqueue. Empty/memory-only commands avoid a transaction as today. Metadata writes use this same primitive and reject the reserved key as user metadata.

Do not prevent default request errors. A synchronous enqueue or callback error attempts abort and waits for the actual terminal event, even if abort throws. Actual abort permits memory revert. Actual complete with latched error poisons before fence release and preserves the original caller error; the marker remains under the stated prefix model. Successful complete requires successful clear. No manufactured terminal timeout. Failures of guard/marker cannot enqueue any body; failed clear may conservatively mark a coherent store dirty. The protocol cannot detect arbitrary browser/storage corruption that violates successful ordered prefix effects, successful clear falsely reported failed with effect, legacy unmarked damage, or independent uncoordinated writers.
